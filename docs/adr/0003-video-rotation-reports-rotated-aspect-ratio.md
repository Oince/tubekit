# 영상 회전은 YouTube가 돌린 비율을 믿게 해서 플레이어 배치를 맡긴다

영상 회전은 플레이어 배치를 직접 CSS로 다시 짜지 않는다. YouTube가 레이아웃 계산에 쓰는 영상 비율을 돌린 비율로 바꿔 주고, YouTube가 계산한 영상 상자 안에서 영상만 돌려 채운다. 데스크톱 YouTube는 플레이어가 알려 주는 영상 비율로 기본·극장·전체화면·미니플레이어·1열 화면의 플레이어 크기와 오른쪽 열 폭을 모두 다시 계산하므로, 이렇게 하면 돌린 영상이 모든 화면에서 그 비율의 진짜 영상과 똑같이 배치된다. 영상만 돌리면 플레이어 밖으로 삐져나오거나, 이를 막으려고 영상을 줄이게 된다. 그것이 이 기능이 피하려는 모습이다.

비율은 YouTube가 업로더용으로 지원하는 강제 비율 키워드 `yt:stretch=W:H`를 플레이어 공개 API `updateVideoData({ keywords })`로 넣어 바꾼다. 플레이어의 `getVideoAspectRatio()`가 이 값을 쓰고, 그 값을 받는 YouTube 페이지 레이아웃도 함께 따라온다.

## Considered Options

- **영상만 CSS로 돌리고 축소해 맞추기**: 기존 확장 프로그램의 방식이다. 플레이어가 원래 비율 그대로라 돌린 영상이 작아지거나 밖으로 나온다. 버렸다.
- **화면별 플레이어 배치를 직접 CSS로 흉내 내기**: YouTube 내부에 덜 기대지만, 화면마다 순정과 어긋날 위험이 크다. YouTube 레이아웃이 바뀔 때마다 따라 고쳐야 한다.

## Consequences

- YouTube 내부의 비율 판단 경로(`yt:stretch` 처리, `updateVideoData`, 페이지 레이아웃의 비율 갱신)에 기대므로, YouTube가 그 부분을 바꾸면 깨질 수 있다.
- YouTube는 영상을 바꿀 때 새 영상에 키워드가 없으면 이전 영상의 키워드를 남기므로, 돌린 채 영상이 바뀌면 남은 `yt:stretch`를 직접 지워야 한다.
- 영상 회전은 모바일 웹(`m.youtube.com`)에 넣지 않는다. 모바일 웹은 진짜 세로 영상에도 인라인 플레이어를 키우지 않고, iPhone Safari에는 요소 전체화면 API가 없어 전체화면이 iOS 기본 영상 플레이어로 넘어가며, 그 플레이어에서는 영상에 준 회전이 풀린다(iOS 27.2 시뮬레이터에서 확인). 순정 플레이어를 유지한 채 돌린 영상을 크게 보여 줄 방법이 없어, 순정과 다른 페이지 안 전체화면을 만드는 대신 빼기로 했다.
