# 2열 화면은 YouTube가 붙이는 표시만으로 한 번 정의하고, 판정·CSS 대비책·감시 목록을 모두 그 정의에서 만든다

**2열 화면**(GLOSSARY) 정의가 바뀔 때마다(v0.6.5, v0.6.13) 세 곳을 손으로 맞춰 왔다. 스크립트 판정, YouTube가 2열을 푸는 순간 패널을 숨기는 CSS 대비책, 바뀌는 속성을 지켜보는 감시 목록이다. 셋이 따로 적혀 있어 어긋날 수 있었고, 실제로 감시 목록에는 판정이 읽는 미니플레이어 표시가 빠져 있었다. 그래서 ADR 0006이 미뤄 둔 대로 2열 화면과 YouTube 패널 판정을 YouTube 어댑터(`src/core/youtube.js`)로 옮겼다. 어댑터는 두 판정 각각에 대해, 판정에 쓰는 조건을 한 번만 적어 둔다. 판정 함수, CSS 셀렉터 조각, 감시할 속성 목록은 모두 그 조건에서 만든다. 댓글 패널은 "2열 화면인가, 전체화면인가, YouTube 패널이 펼쳐져 있나" 세 가지 사실만 받는다. 극장 모드 같은 세부 구분은 어댑터 밖으로 나오지 않는다.

정의는 측정 없이 YouTube가 붙이는 표시만 쓴다. 영상 화면이고, YouTube가 2열이라고 표시했고, 극장 모드도 전체화면도 아니면 2열 화면이다. 측정은 YouTube의 2열 표시를 쓰기 전(0.3.4)에 2열을 알아내던 방법이 남은 것이었다. 2026-11-24에 Chrome에서 창 너비 경계, iPad 가로·세로, 극장 모드, 미니플레이어, 영상 이동, 새로고침을 프레임마다 기록했다. 그 결과 표시와 실제 배치가 어긋난 순간은 미니플레이어를 펼친 직후 약 50ms뿐이었다. 이때는 YouTube가 영상 페이지를 아직 숨겨 둔 상태인데, 이 틈도 2열 화면으로 본다. 그러면 페이지가 보이는 순간 패널이 이미 서 있다. 표시만으로 정의하므로 CSS 대비책이 스크립트 판정과 같은 조건을 쓸 수 있다. 그래서 극장 모드로 바꾸는 순간에도 스크립트를 기다리지 않고 패널이 사라진다.

판정은 변화가 보이는 즉시 하고, 세우기·걷어 내기·보류도 바로 한다. 정비 작업은 지금처럼 모아서 하고 패널 스크롤 중에는 미룬다. 정비 작업이란 댓글 불러오기 상태 확인, 스크롤바 폭 맞추기, 바뀐 관련 목록 따라가기 같은 일이다. 이것을 모으는 것은 0.3.10의 iPad 터치 스크롤 끊김 수정에서 온 규칙이다. 그래서 즉시 판정도 패널 안 댓글이 바뀌는 데에는 반응하지 않는다.

## Considered Options

- **측정을 남겨 두기**: YouTube가 2열이라고 표시하고 실제로는 나란히 놓지 않는 경우를 대비한다. 하지만 그런 순간은 확인되지 않았다. 측정은 극장 모드를 가려내지도 못한다. 극장 모드에서도 오른쪽 열은 큰 플레이어 아래에서 오른쪽에 붙어 있기 때문이다. 또 측정은 CSS로 만들 수 없어, 측정을 남기면 정의가 "표시로 아는 부분"과 "재야 아는 부분" 두 갈래로 나뉜다.
- **극장 모드 외에 전체 폭 플레이어·미니플레이어 표시도 조건에 두기**: 기록에서 이 표시들은 혼자 결과를 바꾼 적이 없었다. 미니플레이어 표시는 아예 나타나지 않았다. 확인되지 않은 경우를 위해 조건을 두지 않는다는 기준으로 뺐다.
- **다시 세우는 쪽은 0.1초 모은 뒤 하기**: YouTube가 관련 동영상 목록을 다 그리기를 기다리자는 것이다. 하지만 목록이 아직 없으면 세우기가 실패하고 다음 변화에 다시 시도하므로, 기다릴 이유가 없었다.

## Consequences

- YouTube가 2열 표시를 실제 배치와 다르게 붙이기 시작하면 이를 걸러 줄 안전장치가 없다. 증상은 패널이 엉뚱한 배치에 뜨는 것이고, 고칠 곳은 어댑터의 정의 한 곳이다.
- 2열 화면 조건을 바꾸면 판정, CSS 대비책, 감시 목록이 함께 바뀐다. 테스트는 CSS 문자열 대신, 정의에서 나온 셀렉터와 감시 목록을 실제 문서에 대 보는 방식으로 확인한다.
