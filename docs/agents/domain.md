# 도메인 문서

엔지니어링 스킬이 코드베이스를 살펴볼 때 이 저장소의 도메인 문서를 어떻게 읽고 쓰는지 정한다.

## 살펴보기 전에 읽을 것

- **`GLOSSARY.md`**(저장소 루트): 기능을 설명하고 논의할 때 쓰는 말을 정한 용어집.
- **`docs/adr/`**: 지금 손댈 부분에 닿는 ADR을 읽는다.

이 파일들이 없으면 **말없이 넘어간다**. 없다고 지적하지 않고, 미리 만들자고 제안하지도 않는다. `/domain-modeling` 스킬(`/grill-with-docs`, `/improve-codebase-architecture`에서 불러 씀)이 용어나 결정이 실제로 정해질 때 그때그때 만든다.

## 파일 구조

이 저장소는 단일 맥락(single-context)이다.

```
/
├── GLOSSARY.md
├── docs/adr/
│   ├── 0001-<slug>.md
│   └── 0002-<slug>.md
└── src/
```

## 용어집의 말을 쓴다

결과물(리팩터 제안, 가설, 테스트 이름, 문서 등)에서 도메인 개념을 가리킬 때는 `GLOSSARY.md`에 정의된 용어를 쓴다. 용어집이 `_Avoid_`로 피하라고 적어 둔 동의어로 바꿔 쓰지 않는다.

필요한 개념이 용어집에 없다면 신호로 본다. 프로젝트가 쓰지 않는 말을 지어내고 있거나(다시 생각한다), 실제로 빠진 용어가 있는 것이다(`/domain-modeling`에서 다루도록 적어 둔다).

## ADR과 어긋나면 드러낸다

결과물이 기존 ADR과 어긋나면 조용히 덮어쓰지 말고 분명히 밝힌다.

> _ADR-0007(…)과 어긋나지만, …때문에 다시 논의할 만하다._
